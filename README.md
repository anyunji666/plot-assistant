# 剧情助手

## 总结功能（总结/状态表）

面板"总结功能"分组下三个按钮：**起始楼层**（沿用同一本总结世界书新开对话继续写时，设定本对话的楼层号从第几层开始编号）、**自动小总结**（按当前对话进度，每30层自动往后总结，支持起始楼层偏移，见下）、**状态存档**（读取当前状态表+已有小总结，生成可粘贴到新对话第0层的存档内容，用于新对话接续时恢复人物关系/物品/伏笔以及时间线/剧情总览）。

- 总结世界书按"角色名 + 总结"命名，与角色卡绑定的世界书无关，不存在会自动创建。
- 状态表：解析每层输出的摘要模块，持久化 Relationships / Inventory / Setups 三项。其中 Inventory / Setups 由独立的"状态表LLM"（面板"状态表配置"按钮里单独配置，可跟随酒馆当前连接或走自定义反代）在每层AI消息渲染完后调用一次提取，是否自动调用由"状态表配置"按钮右侧的**再分析**开关控制（默认关闭，不会自动发请求；开启后每层AI消息渲染完自动调用一次）。
- **起始楼层会记到"本对话"的 chatMetadata 里**（跟着这个对话/存档走，重新打开同一个对话不会丢；换到别的对话、别的角色卡也不会互相干扰）。只有你再次点击"起始楼层"并确认新值时，才会覆盖这个记录——只是重新打开这个对话、不主动点按钮，数字不会变。
- "起始楼层"弹窗里预填的建议值，每次都是**实时重新扫描世界书**算出来的（历史最大止楼层 + 1，世界书为空则是 0），不会用本对话已经保存的值当默认值——避免世界书内容变了、但默认值还停留在旧建议上。
- **自动小总结会自动读取本对话的起始楼层**：没设置过就是 0（不偏移）；设置过就会把新写入的世界书条目楼层号统一加上这个偏移量，读取原始聊天记录仍然用本对话内部的楼层号，只是世界书里保存的标题楼层号变了。不需要区分"是不是接续对话"，一个按钮通用两种场景。
- **设置过起始楼层后，第一次自动小总结会从本对话第2楼开始**（跳过第0楼的"状态存档"粘贴内容和第1楼的接续首条发言），避免把状态存档没有的时间/事件信息误当成新剧情去扫描；后续批次照常往后推进，不受影响。
- **典型用法**：总结完一段故事、重置角色卡或新开一个对话继续写、但仍沿用同一本总结世界书时，先点一次"起始楼层"（弹窗会自动扫描世界书里已有的历史小总结、预填建议的起始楼层，一般直接确认即可），再照常用"自动小总结"往后总结。
- 批次内如果有楼层没输出摘要模块，会调用AI针对这些楼层逐层还原 Time/Location/Overview（用户发言楼层不参与、不需要还原），还原结果和正常楼层的摘要字段一起拼成小总结内容，这一步本身不再经过AI。
- 自动小总结运行时可以点"停止总结"，会在当前还未开始的还原调用之前生效，已经保存的批次不受影响。
- **状态存档**：Relationships / Inventory / Setups 直接读取当前状态表世界书条目，不调用AI。Time 本地拼接已有全部"小总结：起-止"条目的时间头尾，不调用AI。Overview 调用AI——把全部小总结正文按顺序拼进 `<story_history>` 标签交给AI二次提炼，生成一份不超过1000字、保留完整脉络的剧情总览（世界书里还没有任何小总结条目时，Time/Overview 留空，跳过AI调用）。开始新对话后把这条条目内容粘贴到第0层，首次触发状态表全量重放时会自动恢复 Relationships/Inventory/Setups，Time 还能顺带给后续逐层还原摘要用作时间锚点。

（详细规则和已知注意事项参见代码内注释。）

## 同人小说录入

面板"同人小说"分组下的**同人小说录入**按钮，弹出录入面板：顶部一个"读取已创建章节"下拉框，下面一个章节名输入框、一个概述输入框，底部三个按钮**关闭 / 保存 / 下一章**。

- 用途：手动把原著章节名+概述录入世界书，供 AI 查阅参考，而不是依赖模型凭记忆回忆原著细节。
- 存放位置：和总结/状态表/角色卡共用同一本"角色名总结"世界书，标题固定加**「原著章节：」**前缀（如"原著章节：第三章 云隐山遇袭"），和其它条目一样出现在面板下方的"世界书条目"列表里，可以在那里直接展开改正文或删除。
- **新建 vs 编辑**：下拉框默认停在"-- 新建章节 --"，此时保存会新建一条；下拉框选中某个已有章节后自动读入该章节的名字和概述、进入编辑模式，此时保存按 uid 定位更新原条目（支持改章节名而不会产生重复条目）。新建时章节名如果和已有条目重名会报错，不静默覆盖。
- **关闭**：不保存，直接关闭面板。
- **保存**：保存当前内容后关闭面板。
- **下一章**：保存当前内容，但不关闭面板——清空章节名/概述输入框、下拉框回到"-- 新建章节 --"，方便接着录入下一章，不用重新点开按钮。
- 新建的条目默认 `disable: true`（不会自动注入正文），需要的话可以去下方"世界书条目"列表里手动启用；条目本身是常驻类型（不依赖关键词触发），启用后就会持续注入，适合配合"只保留当前章节启用"的用法手动或后续自动切换。

## 摘要提取（合并自独立扩展 novel-summary）

面板"同人小说"分组下的**摘要提取**按钮：点击后弹出确认框"是否在顶部导航栏增加「小说摘要提取」功能"，选"是/否"都会自动关闭该确认框并关闭控制面板本身。

- 本模块是原独立第三方扩展 `novel-summary` 合并进来的，功能不变：上传小说（.txt/.mobi）→ 按设定大小分段 → 逐段调用 AI 压缩为摘要 → 导出 TXT，跟本插件自身的"总结/状态表"是完全独立的两套逻辑，互不影响。
- 顶部导航栏「小说摘要提取」图标**默认不显示**，需要通过"摘要提取"按钮的确认框选"是"才会出现；再次点击选"否"可以隐藏。图标本身在插件加载时就已经注入页面，只是用 CSS 控制显隐，不会因为反复开关而丢失里面的进度。
- API 地址 / Key / 模型 / 提示词等设置在图标弹出的抽屉面板里单独配置，跟本插件其它功能使用的模型/API 无关；仍然是明文保存在插件设置里，本模块处于测试阶段，未做额外加密处理。
- 上传后的原文与分段摘要进度保存在独立的 IndexedDB（`novel-summary-db`），控制面板"清空数据"按钮会一并清空。

## 输出强调（对话前强调）

面板"输出强调"分组下的**对话前强调**按钮：手动维护一条固定提示内容（默认是摘要输出格式协议），内容 + 启用开关，保存后立即写入总结世界书，跟总结/状态表同级存在。

## 角色卡（添加联系人）

面板"联系人"分组下的**添加联系人**按钮，弹出"姓名 + 性别 + 其它"表单（姓名、性别必填，其它选填、支持多行），写入内容会包成：

```
<character_information character="姓名">
gender: 
other: 
</character_information>
```

- 存放位置：和总结/状态表共用同一本"角色名总结"世界书，标题固定加**「角色卡：」**前缀（如"角色卡：欧阳雨柔"）。
- 触发方式：关键词触发（非常驻），关键词按人名自动提取全名 + 去姓简称（如"欧阳雨柔"会同时以"欧阳雨柔"和"雨柔"触发），只有正文提到这个人名才会注入上下文，省 token。
- 编辑/删除：不需要单独入口，新建的角色卡条目会和小总结/状态存档/状态表一样出现在面板下方的"世界书条目"列表里，展开即可直接改正文或删除；改变正文里的 `character="..."` 不会自动重新提取关键词/改标题，需要的话删掉重建。
- 重名：同一个角色名只能存在一条，新建时如果标题已存在会报错，提示你去世界书条目列表里直接编辑那一条。

## 地图标记

- **数据按角色区分**：不需要"绑定某个角色卡"，地图数据（标记点、路线、势力、小地图）自动跟随当前打开的角色卡，切换角色卡即切换到该角色自己的地图数据，互不干扰。群聊或没有选中角色卡时，地图数据只临时存在本地，不会同步进任何世界书。
- **注入方式为世界书条目**：地图内容会自动写入当前角色的"角色名总结"世界书里，固定标题为**「地图信息」**的一条条目。这条条目的内容由插件自动生成和覆盖（不可手动编辑正文）。
- **触发时机**：每次编辑标记、路线、小地图说明/是否加载后，以及切换角色卡时，都会自动重新生成并覆盖这条「地图信息」条目。
- **入口**：只有两个入口，打开的是同一个地图编辑器：
  - 剧情助手控制面板里，"地图"分组下的**「地图标记」**按钮
  - 悬浮球按钮（可拖拽记忆位置）
- **"清除数据"范围**：地图编辑器里的"清除当前角色的地图数据"只清除当前角色的标记/路线/图片，不会影响其他角色的地图数据。

### 使用方式

- 大地图（唯一，世界地图）：标记点 + 势力行动路线。点击地图任意位置添加标记；点"添加路线"后依次点击两个已有标记，填写方位、队伍信息与时间即可生成一条路线。
- 小地图（可多张，村庄/庄园/房间等）：标记点 + 手写的"布局关系/特别说明"，勾选"加载到本次对话的 AI 上下文"决定是否计入「地图信息」。
- 标记/路线数据支持导出导入 JSON（不含图片，图片需重新上传）。
- Leaflet 库文件本地打包在 `lib/leaflet/`，不依赖外网。

### NPC智能行程

- **资料录入**：工具栏「📜 NPC行程」按钮打开一个自由格式文本框，把NPC的活动规律/日程手写或粘贴进去即可，不需要固定模板，按角色卡分别存储。
- **开关**：工具栏「NPC智能行程」勾选框，默认关闭，按角色卡分别记忆。打开后，每层AI消息渲染完成会自动跑一次：结合NPC行程资料 + 最新一层剧情正文，判断资料中出现的NPC此刻各自在大地图/已勾选加载的小地图的哪个已有标记点，写进对应标记的"当前NPC"栏位（标记编辑弹窗里"地点描述"/"标记名称"下方可见，也可随时手动改，但下次自动更新会整体覆盖式重写）。
- **手动刷新**：不想等下一层AI消息，可以在「NPC行程」面板里点"立即刷新NPC位置"手动触发一次（需要先打开上面的开关）。
- **地点匹配规则**：LLM只能从当前地图已有的标记点里选，选不出合适地点就跳过该NPC，不会自动新建标记、不会编造地点。
- **与主线剧情的联动**：只要标记上填了"当前NPC"（不管是自动写的还是手动填的），都会拼进「地图信息」世界书条目，让主线剧情LLM也能感知到"现在谁在哪"。
- **独立LLM连接**：工具栏「⚙️NPC模型」按钮可配置这次判断专用的API连接（留空则跟随酒馆当前对话连接），与剧情LLM、状态表LLM三者互相独立、互不影响。

## 手机（通讯器）私信系统

右下角「通讯器」悬浮球（默认关闭，去控制面板顶部按钮打开）点开后是一部克莱因蓝配色的小手机，三个页签：**通讯录 / 背包 / 设置**。

- **通讯录**：读取当前「角色名总结」世界书里所有「角色卡：」前缀的条目（即"添加联系人"功能建的那些），只显示头像/姓名/性别，点开进入和该角色的聊天页。
- **聊天**：私信正文存在本地 IndexedDB（跟地图图片是两个独立的库，不占世界书 token），key 先按"当前角色卡"分一层，再按"联系人名+日期"分组，避免不同角色卡下同名联系人的私信互相串；可以在"设置"页里按角色清空。
- **忙/闲判定**：给角色发消息时，先用**纯文本匹配**看角色名（含去姓简称）是否出现在最后一层 AI 楼层正文里：
  - **不出现（闲）**：直接判"闲"，不调用 AI。
  - **出现**：进一步调用一次 AI，结合角色人设、当前关系阶段和最后一层正文，判断这个角色此刻**有没有空**看/回私信：
    - **有空**：仍按"闲"处理，正常生成回复。
    - **没空（忙）**：写入 chatMetadata 的忙碌标记，立即重算一次状态表，让正文 AI 在状态表里看到 `Busy: 角色名: 忙`。正文 AI 只要这个角色某一轮不再出现在场景里，就需要在自己的摘要块里输出 `Busy: 角色名: [REMOVE]`；插件下次重算状态表时读到这个信号，会自动帮该角色补发一条私信回复。
  - 只要最后一层楼层号没变，同一个角色的判断结果会被记住，连续发消息不会重复判断。
- **回复生成的提示词**：会把该联系人的**全部历史私信**（按 storyTime 分组，storyTime 变化时另起一行标注"时间：xxx  当前俩人关系阶段：xxx"，关系阶段实时从状态表 Relationships 读取）连同角色卡、最后一层正文一起发给 AI。其中"扮演谁 + 口吻参考人设"这句开场白是**可编辑预设**——面板"联系人"分组下的**私信预设**按钮可以打开编辑框修改，其余结构和输出格式要求写死在代码里，不随预设一起改动。
- **私信槽位**：只要有新的私信更新（不管是你发的还是角色回的），下一次正文生成前会临时把当天的聊天记录注入正文（通过 `context.setExtensionPrompt`），生成完这一轮立即清空，不会常驻占用上下文。
